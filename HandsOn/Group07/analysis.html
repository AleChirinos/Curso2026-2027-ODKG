1. Dataset analysis

DBtrainrides.csv was read in full: UTF-8, comma-separated, header included, no sep=, directive. It contains 296 line labels and 1,292 raw locality labels (1,283 after trimming).

Quality checks and cleaning

FindingDecision
Missing values
211,355 planned arrivals; 475,630 updated arrivals; 339,926 updated departures. No planned departure is missing.		Keep columns and records. Omit RDF triples for empty cells. Compare planned/updated times only when both exist.
Zero delays without updates
Every missing updated time has a reported delay of 0.		Keep the source zero, but do not treat it as proof of an observed on-time event. Missing information does not establish cancellation.
Delay consistency
No mismatch across 1,585,720 comparable arrivals and 1,721,431 departures. Seven updated arrivals have no planned arrival.		Reported delay matches updated − planned time. The source labels also consistently use delay for > 5 minutes.
Repeated records
6,725 duplicate rows; 31,463 repeated ID occurrences, including 24,738 differing from the first record for their ID.		Merge identical rows in RDF; distinguish different observations sharing an ID (section 3).
Text and postal codes
58,092 rows have outer city whitespace; 115,126 postal codes have four digits.		Trim city labels. Validate postal codes before restoring a leading zero; preserve originals.
Other missing fields
211,355 paths; 1,416,016 messages (68.69%).		Keep paths as ordered strings. A missing message does not prove absence of disruption.
Station metadata
Name, category, locality, state, postal code and coordinates are consistent per EVA ID.		Reuse one Station resource per EVA ID.

Reading the times: plan = scheduled time; change = updated time known at collection, not necessarily an actual recorded event. Arrival before departure is normal at a stop. Missing planned arrivals may indicate a starting station or unavailable data; the CSV cannot establish the cause.

Use ISO 8601 timestamps without inventing a time-zone offset. Scheduled events span 7–15 July, beyond the collection dates. Arrival–departure ordering has not been checked across the full file.

Hash URIs for vocabulary terms; slash URIs for individuals. https://example.org/db-delays/ is an illustrative base to replace with a controlled domain before publication. [4]

Classes use UpperCamelCase; properties use lowerCamelCase. Keep properties directly in the vocabulary namespace, and use the same base in HTML, ontology and example RDF. [5]

  • Keep IDs and EVA numbers as strings. A line label is not a train or journey key.
  • Trim place labels, normalise Unicode to NFC, and percent-encode each path segment in UTF-8; e.g. Bad Homburg → Bad%20Homburg. Preserve case and punctuation.
  • Keep a persistent place-to-URI mapping so label corrections do not change established identities.
TrainStop fingerprint: reproducible rule and example

SHA-256 of a UTF-8 JSON array of the 20 original cell strings in header order, before cleaning; use ensure_ascii=False and separators=(',', ':'). Retain the ID as stopId and document the source version. The fingerprint does not imply a collection timestamp.

Publication design

Serve ontology terms as Turtle or HTML via content negotiation. For individuals, use 303 See Other to a description document, with Vary: Accept. These endpoints are proposed, not deployed.

Deliverables: vocabulary in ontology/*.ttl; individuals in ontology/*-example.ttl. [5]
