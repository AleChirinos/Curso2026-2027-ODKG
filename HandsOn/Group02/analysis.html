Dataset & Licensing Analysis

1. Dataset Analysis

We analyzed two datasets: CPD_Facilities and CPD_Park_Art. Below are the key findings regarding their schema, quantities, and data cleaning requirements to be executed in OpenRefine:

1.1. Chicago Park District Facilities Dataset

  • Quantities: 4,467 rows and 9 columns.
  • Null Values: Very clean data, only 1 missing value in FACILITY_N and 1 in FACILITY_T.
  • Unique Values: Contains 549 unique parks, 75 unique facility names (e.g., "CULTURAL CENTER", "PLAYGROUND"), and 3 main facility categories (FACILITY_T).
  • Data Type Issues:
    • The coordinate columns (X_COORD, Y_COORD) use commas as decimal separators (e.g., -87,52486664). We must apply a text transform: value.replace(",", ".") and convert the column to numeric.
    • OBJECTID_1 and PARK_NO should be converted to numeric integers.

1.2. Chicago Park District Park Art Dataset

  • Quantities: 346 rows and 11 columns.
  • Null Values: Contains missing data in ARTIST (15 nulls), OWNER (53 nulls), and OFFICIAL_N (164 nulls).
  • Unique Values: 117 unique parks containing art, and 263 unique artists.
  • Data Type Issues:
    • Similar to the facilities data, X_COORD and Y_COORD contain commas instead of decimals and must be transformed and cast to floats.
    • Blank cells in the ARTIST column should be filled as "Unknown Artist" to avoid mapping errors during RDF generation.

2. Licensing Analysis

  • Publisher: City of Chicago (Chicago Data Portal)
  • Rightsholder: Chicago Park District
  • Original License: The data portal provides the raw datasets under a "Public Domain" designation. However, their Terms of Use states that secondary applications utilizing modified data must feature a specific legal disclaimer acknowledging the City of Chicago as the source and disclaiming liability.
  • Proposed License: Because the source data is Public Domain, we will publish the generated RDF datasets under a Creative Commons Attribution 4.0 International (CC BY 4.0) license. This satisfies the requirement to credit the City of Chicago while allowing the data to be freely shared, linked, and adapted.

3. Resource Naming Strategy

To ensure our RDF graph is linked appropriately, we have defined the following URI architecture:

Domain & Paths

  • Base Domain: http://smartcity.chicago.es
  • Ontology Path: http://smartcity.chicago.es/ontology/ParkExplorer#
  • Data/Resource Path: http://smartcity.chicago.es/resource/

Class & Property URI Patterns

  • Classes: CamelCase (e.g., http://smartcity.chicago.es/ontology/ParkExplorer#Artwork)
  • Properties: camelCase (e.g., http://smartcity.chicago.es/ontology/ParkExplorer#hasFacility)

Instance Naming Patterns

Concept / Class URI Pattern Example
Park /resource/Park/{PARK_NO} .../resource/Park/165
Facility /resource/Facility/{OBJECTID_1} .../resource/Facility/2494
